    API reference¶

    The public API is importable from amesml. Modules are documented below in pipeline order.

    amesml.config ¶

    Training configuration.

    A :class:TrainConfig records every choice that changes a trained model. It is saved inside each model's metadata.json, so any model can be retrained exactly from its own metadata.

    The defaults reproduce the original notebook: an unregularised linear model (or a logistic regression for classification) on the raw Ames columns, with an 80/20 split seeded with 42.

    TrainConfig dataclass ¶

    Everything that determines how a model is trained.

    Attributes:

    Name Type Description
    task TaskType

    "regression" predicts the sale price; "classification" predicts whether a house sells at or above threshold.
    model ModelType

    Estimator family. linear is ordinary least squares (or logistic regression for classification), ridge and lasso add L2 and L1 penalties, gbm is histogram gradient boosting.
    target str

    Name of the sale-price column.
    id_column str | None

    Identifier column that is never used as a feature.
    test_size float

    Fraction of rows held out for evaluation.
    random_state int

    Seed for the train/test split and every seeded estimator.
    threshold Threshold

    Price separating the two classes, or "median" to use the median sale price of the training split.
    stratify bool

    Keep the class balance equal across the split. Only valid for classification.
    engineer_features bool

    Add the derived features from :mod:amesml.features (total area, ages, bathrooms, porch area).
    numeric_features tuple[str, ...] | None

    Use exactly these numeric columns instead of inferring them from the data.
    categorical_features tuple[str, ...] | None

    Use exactly these categorical columns instead of inferring them from the data.
    categorical_codes tuple[str, ...]

    Columns stored as numbers that are really category codes, such as the dwelling-type code MSSubClass.
    zero_fill_features tuple[str, ...]

    Numeric columns where a missing value means "none of this", so they are filled with 0 instead of the median.
    drop_first bool

    Drop the first level of each one-hot encoded column, as the notebook did. This avoids the dummy-variable trap for the unregularised models.
    alpha float | None

    Regularisation strength for ridge and lasso. None selects the cross-validated default in :data:DEFAULT_ALPHAS.
    max_iter int

    Iteration limit for the iterative solvers.

    resolved_alpha property ¶

    resolved_alpha: float | None

    The regularisation strength actually used, after applying defaults.

    amesml.data ¶

    Loading, validating and splitting the Ames Housing dataset.

    The dataset is the Kaggle "House Prices: Advanced Regression Techniques" train.csv: 1,460 sales from Ames, Iowa, with 79 candidate features, an Id and the target SalePrice (De Cock, 2011).

    In this file the string "NA" is a value, not an accident: it means the house has no pool, no alley access, no basement, and so on. Elsewhere the literal word "None" is a real category (MasVnrType == "None"), so pandas' default list of missing-value markers - which includes "None" - would silently destroy information. :func:read_ames_csv therefore treats only "NA" and empty fields as missing, exactly as the original notebook did.

    dataset_fingerprint ¶

    dataset_fingerprint(frame: DataFrame) -> str

    Return a SHA-256 of the frame's contents, independent of platform.

    Used in model metadata to record exactly which data a model was trained on. The frame is serialised as CSV with \n line endings so the same data hashes identically on every operating system.

    amesml.features ¶

    Derived features for the Ames data.

    Each function takes a frame with the raw Ames columns and returns one new column as a Series, without modifying its input. :func:add_engineered_features applies all of them at once and is what the training pipeline uses when TrainConfig.engineer_features is enabled, so a saved model recomputes these columns from raw inputs at prediction time.

    The original notebook did not engineer features; these are the standard Ames derivations. They are opt-in so that the default models reproduce the notebook's published results exactly. See docs/benchmarks.md for their effect.

    amesml.preprocess ¶

    Column typing and the scikit-learn preprocessing transformer.

    The transformer reproduces the notebook's choices, which follow from what a missing value means in this dataset:

    • Numeric gaps are filled with the training median - except columns listed in zero_fill_cols (MasVnrArea, GarageYrBlt), where a gap means the feature is absent rather than unknown.
    • Categorical gaps become the explicit level "Missing". NA in Ames means "no pool", "no basement" and so on; filling it with the most frequent level would claim that houses without a pool have the most common pool quality.
    • Category codes stored as numbers (MSSubClass, MoSold) get their own branch, filled with the most frequent code, because a column cannot mix the string "Missing" with integers and still be encoded.

    normalise_missing ¶

    normalise_missing(values: Any) -> Any

    Return values as an object array with every missing marker as NaN.

    SimpleImputer only recognises NaN. In an object column - what pandas 2 builds from Python objects - None and pd.NA would otherwise survive imputation and become a category of their own.

    amesml.models ¶

    Training, saving, loading and prediction.

    A trained model is an ordinary scikit-learn Pipeline with a few extra fitted attributes that make it self-describing:

    task_ "regression" or "classification". input_features_ The raw columns the pipeline expects, in order. input_kinds_ "number" or "text" for each input column, used to coerce inputs. feature_defaults_ The most common training value of each input (the median for numeric measurements), used for any column an input leaves out. threshold_ Classification only: the price separating the two classes. training_data_sha256_ Fingerprint of the rows the pipeline was fitted on. amesml_config_ The :class:~amesml.config.TrainConfig used, as a dictionary.

    On disk a model is a directory holding model.joblib and metadata.json (and metrics.json when it came from :func:train).

    l1_logistic_regression ¶

    l1_logistic_regression(c: float, *, random_state: int, max_iter: int) -> Any

    L1-penalised logistic regression across scikit-learn versions.

    scikit-learn 1.8 deprecated penalty= (removal in 1.10) in favour of l1_ratio, but before 1.8 l1_ratio was ignored unless penalty="elasticnet". liblinear supports L1 everywhere and is far faster than saga on data of this size, with identical results.

    amesml.api ¶

    REST inference service.

    Install with pip install "amesml[api]" and start it with amesml serve, or run uvicorn amesml.api:app with AMESML_MODEL_PATH set.

    Models are loaded once, when the application starts. AMESML_MODEL_PATH (or create_app(model_paths=...)) may list one regression and one classification model, separated by commas, so a single process can serve both endpoints.

    Pydantic and FastAPI evaluate annotations at runtime, and Python 3.9 cannot evaluate X | None; this module therefore spells unions with Optional and Union and does not use from __future__ import annotations.

    PredictRequest ¶

    Bases: BaseModel

    Each record maps Ames column names to values. A field you leave out takes the model's typical training value; a field sent as null means the feature is absent - "PoolQC": null says the house has no pool.
